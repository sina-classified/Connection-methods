# Contributing Guide

Thank you for contributing to this repository.

This project focuses on:

* internet censorship research
* circumvention methods
* networking protocols
* DPI evasion techniques
* connectivity tools
* measurement and analysis

Please keep contributions technical, structured, and verifiable.

---

# Before Contributing

Please:

* search existing issues and pull requests first
* avoid duplicate entries
* verify information before submitting
* use clear technical descriptions
* provide sources whenever possible

---

# Contribution Types

You can contribute:

## Documentation

* protocol explanations
* setup guides
* tutorials
* comparison tables
* architecture diagrams

## Research

* censorship analysis
* DPI behavior observations
* ISP testing
* outage reports
* protocol benchmarks

## Tools

* clients
* servers
* monitoring utilities
* scripts
* testing utilities

## Improvements

* typo fixes
* formatting cleanup
* better organization
* translation improvements

---

# Repository Structure

Please place content in the correct directory.

Examples:

| Content               | Directory      |
| --------------------- | -------------- |
| VPN protocol          | `/protocols`   |
| Client software       | `/clients`     |
| DNS methods           | `/dns`         |
| DPI evasion           | `/dpi-evasion` |
| Iran ISP observations | `/iran`        |
| Monitoring tools      | `/monitoring`  |

---

# Markdown Standards

Use:

* clear headings
* markdown tables
* bullet points
* code blocks
* consistent formatting

Example:

```markdown
# Protocol Name

## Overview
## Advantages
## Disadvantages
## Detection Resistance
## Iran Compatibility
## References
```

---

# Pull Request Rules

Please:

* keep pull requests focused
* avoid unrelated changes
* explain what was added or changed
* include screenshots when relevant
* include references for technical claims

Large pull requests may take longer to review.

---

# Security Rules

Do NOT submit:

* malware
* credential stealers
* unauthorized access tools
* leaked credentials
* exposed infrastructure
* private user information

Do NOT include:

* API keys
* passwords
* active tokens
* private VPN credentials

---

# Testing Notes

If sharing test results, include:

* ISP name
* country
* date tested
* protocol used
* transport used
* success/failure details

Example:

| ISP | Protocol | Transport | Status  | Date       |
| --- | -------- | --------- | ------- | ---------- |
| MCI | VLESS    | Reality   | Working | 2026-05-29 |

---

# Sources and References

Preferred sources:

* official documentation
* GitHub repositories
* academic papers
* OONI reports
* technical blogs
* packet captures
* reproducible testing

Avoid:

* unverifiable claims
* rumors
* low-quality reposts

---

# Code Style

Scripts should:

* be readable
* contain comments
* avoid obfuscation
* explain dependencies
* avoid unnecessary complexity

# Respectful Collaboration

Please keep discussions:

* technical
* respectful
* constructive
* evidence-based

Contributors from all regions and backgrounds are welcome.
